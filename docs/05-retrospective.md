# 实现复盘

## 最难的问题

预算不是一次静态报价。估算本身耗时，工具失败也消耗额度，保存还需要预留时间。如果每次改计划都重新从零算，方案会在表面满足约束的同时超支。

实现将费用公式集中在同一模块：估算使用“已发生消耗＋未完成步骤＋保存”，执行前再次验证剩余计划，失败记录保留，续跑复用成功结果。这样估算、实际执行和恢复使用同一口径。

另一个难点是把模型决策与程序底线区分开。模型决定选材和下一动作；程序负责检查 ID、依赖、预算、时间、持久化成功与否。离线 Mock 单独实现和标识，避免把确定性分支包装成真实 ReAct。

## 学习与取舍

- 先定义可手算的费率和最小数据，再写测试，能快速发现漏算估算/保存耗时的问题。
- “估算工具成功，但方案不可行”需要两层状态；不能把工具是否成功与业务是否可行混为一谈。
- 保存结果必须以数据库为准。唯一请求 ID 与事务能让重复执行、防重和恢复有可检查的证据。
- 固定的 Mock 路径便于回归，但真实模型路径必须实际运行后评估，不能从离线测试推断。
- 引用 ID 合法不代表每一句文案都有素材依据。真实运行发现了额外的体验承诺，收紧生成提示词后重跑，保留前后记录说明改进结果。
