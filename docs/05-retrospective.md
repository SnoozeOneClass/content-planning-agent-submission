# 项目复盘与学习收获

## 最难的问题

最难的部分是把题面中的“合理重规划”转成具体、可计算的业务行为。我首先梳理任务计划与最终方案、参考素材与生成脚本、工具报价与已发生费用之间的关系，再据此确定输入、工具职责和完成标准。

在方案讨论中，我发现固定单次生成费会限制调整空间，因此提出让生成成本随选用素材数量变化，同时保持素材作为参考资料的定位。这个决定使选材成为模型需要完成的业务判断，调整前后的效果也能用同一套公式验证。

另一个难点是动态调整之后，账仍然要算对。估算本身耗时，失败调用也消耗额度，保存还要预留时间。最终实现使用“已发生消耗＋尚未完成步骤＋保存”计算预计总量，并在执行前再次检查。成功结果保留，原有消耗不清零，使重规划与失败续跑能够使用一致的约束。

## 学习收获

### 先把业务问题说清楚 再确定实现方式

字段和工具定义直接影响 Agent 的决策空间。先建立能够手算的费用、时间和小规模数据，再讨论行为与成功标准，可以让后续实现和测试围绕同一套业务规则展开。

控制范围是这次重要的工程取舍。我将实现重点放在题目要求的动态决策、预算与时间约束、失败处理和重复执行，优先完成核心链路与异常场景。

### 模型判断与程序约束需要各自明确

模型负责结合主题选择素材，并根据工具反馈决定调整、重试或停止；程序负责准确计算费用、校验依赖、限制执行次数和确认保存结果。这种分工让动态决策有空间，也让硬性约束有可靠的执行依据。

状态需要分层记录：工具是否执行成功、方案是否满足约束、成果是否已保存，分别对应不同的判断。把这些状态与工具返回关联起来，能够定位失败环节，并明确哪些成果可以继续使用。

### 验收需要能回到实际输入和执行记录

我要求在完成实现后增加独立子 Agent 验收，并再次核对交付规范，重点检查费用计算、失败记录、防重复和成功步骤复用，确保结论能够追溯到输入、命令和实际输出。

真实运行进一步完善了验证方式。首轮内容复核发现缺少依据的宣传表述后，AI 助手调整提示词并重跑，形成了自动断言与内容核对相结合的检查流程。后续改进也将同时比较任务状态、执行消耗和实际生成内容。

## 完成情况

本次题目范围内的核心链路和必验场景均已完成，包含正常生成、缺信息处理、工具失败、预算超限和重复执行，并实现了失败步骤续跑。34 项自动化测试、12 组离线验收及 12 组真实模式验收通过，详细结果见[评估文档](03-evaluation.md)。

代码、数据、文档和运行材料已发布到公开 GitHub 仓库。后续工作集中在更广输入下的稳定性和生成效果优化。

## 后续优化

1. **扩展回归输入。** 增加不同主题表达、预算和时间临界组合，观察选材、消耗和最终状态，提升对新输入的覆盖程度。
2. **补充异常组合测试。** 在现有故障注入基础上组合连续失败、保存前失败和剩余额度不足等条件，检查重试、停止及成果保留的判断是否一致。
3. **比较提示词与检索效果。** 固定输入集，对比不同提示词或匹配方式下的动作路径、费用和内容相关性，依据实际结果选择改进方案。
