# 笔试通用考核与 GitHub 交付规范

本规范适用于四选一笔试中的任意题目。选题后，还需补充所选题目的业务要求和全部验收点。

以下考核规则和交付规范依据用户提供的公司笔试说明整理；文末检查清单用于逐项核对，不增加考核要求。

## 一 考核规则

### 考核目标

能理解业务问题，借助 AI 完成可运行项目，并用测试证明效果；观察工程基础、主动学习与改进能力。

### 完成范围

建议投入 **3 小时**，优先完成核心链路；记录实际用时和未完成部分。

界面、线上部署、多 Agent、生产级 Runtime 均非必需。

### 技术选择

语言、模型与框架自选；可用 Google ADK、AgentScope、LangGraph 等，也可原生实现。

框架名称不加分，能解释取舍与修改结果才有价值。

### 运行方式

CLI、HTTP API、Notebook 三选一；必须给出可复制的运行命令或执行步骤。截图、视频不能替代代码。

### 模型与工具

业务工具可以使用本地函数或 Mock。

模型不可用时提供离线 Mock 入口并标明边界；**Mock 只验证流程，不证明真实模型决策效果。**

### 提交方式

提交以下三项：

- 题号。
- GitHub URL。
- 最终 commit SHA。

私有仓库须让指定评审账号可读。所有材料放在同一仓库，不提交真实密钥或隐私数据。

### Agent 决策要求

至少实现一个以下循环：

```text
模型选择动作 → 执行工具 → 观察结果 → 模型调整下一步或结束
```

允许采用预设流程作为执行骨架；**仅有固定条件分支、自动重试或预设决策日志，不视为完成 ReAct 决策要求。**

须提供至少 **两条执行路径** 的运行记录，体现模型根据不同工具结果调整动作。记录应包含：

- 步骤。
- 工具参数。
- 返回摘要。
- 后续动作。
- 简要决策依据。

无须提交模型内部思维过程。

项目须设置**执行步数或工具调用次数上限**，达到上限时返回明确的**未完成状态**。

## 二 GitHub 交付规范

### 项目内容与目录

项目目录可按技术栈调整，但须包含下列代码、文档与验证材料。文档应准确说明需求、设计取舍、运行结果及已知限制，不设篇幅要求。

```text
项目根目录/
├── README.md                    # 环境、安装、运行、评审入口
├── src/                         # 项目代码与模型/工具接入
├── tests/                       # 可执行测试
├── examples/                    # 输入、实际输出、Trace、测试结果
├── data/                        # 合成资料和规则，按题目需要
├── docs/
│   ├── 00-assessment-guidelines.md  # 本文，记录通用规则
│   ├── 01-requirements.md        # 用户、目标、范围和成功标准
│   ├── 02-solution.md            # 调用流程、动态决策、技术取舍
│   ├── 03-evaluation.md          # 测试预期、实际结果、失败和限制
│   ├── 04-ai-usage.md            # AI 辅助内容、个人修改及验证
│   └── 05-retrospective.md       # 最难问题、学习收获、下一步
├── 依赖文件                     # 如 requirements.txt / package.json
└── .env.example                 # 所需变量；无变量时注明无需配置
```

以上为交付内容示意，具体依赖文件按所选技术栈确定。`00-assessment-guidelines.md` 为本项目增加的规则记录文件。

### 验证材料

至少提交 **3 组输入、实际输出及运行记录**，覆盖以下场景：

| 场景 | 需要提交的材料 |
| --- | --- |
| 正常 | 输入、实际输出、运行记录 |
| 信息或资料不足 | 输入、实际输出、运行记录 |
| 工具失败 | 输入、实际输出、运行记录 |

验证材料还须覆盖所选题的**全部验收点**；同一用例可覆盖多个验收点。

Trace 与测试结果存放于 `examples/`，评估文档 `docs/03-evaluation.md` 须引用对应文件。

上述三类场景要求与前文至少两条动态决策执行路径的要求同时适用，可由同一批用例覆盖。

### 框架使用说明

采用框架时，注明：

- 框架版本。
- 使用的功能。
- 框架承担的职责。

无须重新实现框架本身。

### 题面提供的项目结构示例

示例仓库：`lwz1357/agent-campus-submission-example`。

题面说明该仓库公开，可直接查看。示例覆盖目录结构、文档组织与离线运行，**未实现真实模型驱动的 ReAct 决策，不作为完整参考答案或达标依据。**

## 三 交付检查清单

以下项目待实现和验证后逐项勾选。

- [ ] 已确定题号，并整理所选题目的业务要求及全部验收点。
- [ ] 核心链路可运行，README 提供环境、安装说明、可复制的运行步骤和评审入口。
- [ ] 已实现模型选择动作、执行工具、观察结果、调整下一步或结束的决策循环。
- [ ] 至少两条执行路径展示模型根据不同工具结果调整动作。
- [ ] 运行记录包含步骤、工具参数、返回摘要、后续动作及简要决策依据。
- [ ] 设置执行步数或工具调用次数上限，达到上限时明确返回未完成状态。
- [ ] 模型不可用时可运行离线 Mock，并明确其仅验证流程的边界。
- [ ] 提供可执行测试，以及至少 3 组输入、实际输出和运行记录。
- [ ] 验证材料覆盖正常、信息或资料不足、工具失败场景，并覆盖所选题全部验收点。
- [ ] Trace 与测试结果存放在 `examples/`，评估文档引用对应文件。
- [ ] README、代码、测试、所需数据、五份规定文档、依赖文件和 `.env.example` 齐全。
- [ ] 如采用框架，注明版本、使用的功能及承担的职责。
- [ ] 记录实际用时、未完成部分、失败和已知限制。
- [ ] 如实说明 AI 辅助内容、个人修改和验证，并记录复盘。
- [ ] 所有材料在同一仓库，未提交真实密钥或隐私数据。
- [ ] 已准备题号、GitHub URL、最终 commit SHA；私有仓库已向指定评审账号开放读取权限。
