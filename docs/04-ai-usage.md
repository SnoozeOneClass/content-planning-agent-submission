# AI 辅助使用与个人决策

本项目采用 AI 辅助开发。我负责题意澄清、业务约束、范围取舍和验收要求；AI 助手负责代码实现、测试执行、运行记录生成及文档整理。项目通过多轮方案调整，将业务要求落实为可计算的规则和可复核的执行结果。

## 我推动的关键方案修改

### 让费用模型支持有意义的重规划

讨论初期，方案将各工具费用设为固定单次值。我注意到，如果生成工具只有一种固定规格，调整计划主要只能减少脚本数量，素材选择对成本几乎没有影响。这会让“重新规划”的业务意义比较弱。

我提出将生成费用和耗时与实际使用的参考素材数量关联，并将素材限定为生成脚本的参考资料。最终确定：检索按次固定；生成费用为 `2 + 2*n`，耗时为 `10 + 5*n`；估算和保存不收费，但都计耗时。

这个修改把重规划变成了可检验的选材决策。同样生成一条脚本，使用四份素材的总费用为 12，选择两份后为 8。模型结合主题选择素材，成本估算工具核算调整后的费用与时间，实际效果可以通过[真实重规划记录](../examples/real/replan.trace.md)复核。

### 把时间和预算转成一致的数据约束

我提出让用户直接输入剩余时间额度，数值不附单位，并要求全部工具使用同一时间尺度。这形成了 `budget` 和 `time_budget` 两个明确的输入约束。

我将费用与耗时分开定义，明确免费工具同样占用时间，并统一使用题目内的模拟费率。这使预算判断、截止时间检查和失败后的剩余额度计算使用一致的口径。

### 按验收点控制数据和功能范围

我要求先明确数据格式和可自检的样例，再进入实现，并依据验收点收缩初稿范围，删除了素材重复度分析和直接复用已有稿件的设想。合成素材保持为参考资料，Agent 依据主题相关性选材。

最终素材本体只保留 `material_id`、`topic`、`content`，检索时再返回相关度。每个字段都服务于检索、选择、生成输入或执行记录。这个取舍让实现精力集中在预算计算、动态决策、失败处理和重复执行等验收点上。

### 要求可追溯的交付与独立验收

我在实现前确认了用边界输入核对实际结果的方向，并在本地实现完成后要求独立子 Agent 模拟评审，随后按 GitHub 交付规范逐项核对文件与运行材料。

独立子 Agent 重新执行原测试和 CLI，增加预算、时间边界检查，并独立复算已有真实 Trace 的消耗，结果见[独立验收报告](06-independent-acceptance.md)。

## AI 完成的实现与验证

AI 助手根据上述约束实现了 Python CLI、四个业务工具、DeepSeek 接入、SQLite 状态保存、防重复、失败续跑、执行上限和测试程序。我指定了 DeepSeek 并在本地配置密钥；密钥没有进入仓库。

实际验证由 AI 助手执行并保存原始材料：

- [34 项自动化测试](../examples/test-results.txt)：检查费用、时间、依赖、失败记账、保存、防重复和恢复等行为。
- [12 组离线验收](../examples/mock/results.json)：验证工具流程、记账和状态。
- [12 组真实模型验收](../examples/real/results.json)：记录模型根据工具反馈继续、调整或停止的实际路径。

真实调用和离线 Mock 分别实现、分别记录。Trace 由程序运行生成，保留工具参数、返回摘要、后续动作及简短依据。

## 运行结果推动的改进

首轮真实运行后，AI 助手通过内容复核发现“无需来回切换工具”“新手快速开始”等缺少素材支持的表述，随后调整生成提示词并完整重跑。[修改前输出与复核记录](../examples/iterations/writer-v1/review.md)保留了这一改进过程。

这次改进形成了两层检查：程序校验结构与引用范围，内容复核检查事实依据。最终 12 组真实模式用例通过程序化验收，核验范围和结果见[测试与评估](03-evaluation.md)。

实现过程中参考了题面示例、CrewAI 营销示例、LangGraph 计划执行示例和官方工具调用文档，用于理解交付组织与调用方式。具体取舍及接入依据见[方案文档](02-solution.md)。
