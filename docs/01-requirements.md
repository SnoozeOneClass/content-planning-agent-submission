# 内容任务规划 Agent 需求

## 用户与目标

为运营人员在给定主题、预算与截止时间约束下制作并保存一份内容活动方案。核心成果包含选定参考资料、实际生成的脚本、任务计划、步骤状态、工具结果及费用合计；无法完成时保留已有成果并说明原因。

## 已确认范围

- 运行入口采用 CLI，Python 标准库实现，不依赖界面、部署或多 Agent。
- 用户必填 `topic`、`budget`、`time_budget`。后者是相对截止时间，采用统一模拟时间尺度，不填写单位。
- 可选 `request_id` 支持重复执行防重；可选 `script_count` 默认一条，用于验证多步任务的部分成功与续跑。
- 素材只包含参考资料，不提供已有脚本复用，不分析资料重复度。
- 素材静态字段只有 `material_id`、`topic`、`content`。检索结果增加 `relevance_score` 并按其排序。
- 四个业务工具为素材检索、脚本生成、成本估算、方案保存；费用与耗时遵循已确认的[工具表](tool-cost-and-time.md)。
- 所有费用均为题目内的模拟费用，不计算真实模型账单。

## 数据与工具

`data/materials.json` 提供两个主题、八份合成参考资料。`data/tool_rates.json` 为统一费率来源，估算和执行共用。检索采用本地字符二元组和主题匹配分，不声称该分数是向量相似度。

输入检查不替用户补预算或时间。用户要求的脚本数量作为硬约束；超限时可减少每条脚本使用的参考资料，但不得省略用户要求的成果。

## 成功标准

| 验收点 | 可验证标准 | 入口 |
| --- | --- | --- |
| 正常完成 | 实际脚本数量正确；方案真实保存；消耗不超限 | `examples/inputs/normal.json` |
| 缺预算或截止时间 | 返回 `needs_input` 和缺失字段，不开始调用工具 | `missing-budget.json`、`missing-time.json` |
| 工具失败 | 失败不能标为成功，模型看到实际错误后调整或停止 | `tool-failure.json`、`save-failure.json` |
| 预算超限 | 重新估算可行方案，或返回未完成及缺口 | `replan.json`、`over-budget.json` |
| 重复执行 | 同一请求只保存一份方案，不新增执行或消耗 | `repeat.json` |
| 截止约束 | 生成前校验剩余计划含保存的总耗时 | `out-of-time.json` |
| 执行上限 | 达到上限返回 `incomplete` 和 `STEP_LIMIT` | `step-limit.json` |
| 失败步骤续跑 | 已成功脚本、费用和时间保留，只执行剩余步骤 | `partial-resume.json` |

至少三组实际输入、输出和 Trace 覆盖正常、信息不足与工具失败，并覆盖全部验收点。真实模型还需至少两条根据不同工具结果调整动作的路径；Mock 不能作为这一项的证明。

## 完成与失败语义

`completed` 要求本地数据库保存成功；`needs_input` 表示缺少必填输入；`incomplete` 表示工具、模型、约束或步数上限导致未完成。失败步骤保留失败记录，即使后续成功也不改写历史。

启动后的工具失败仍消耗本次费用与时间，避免失败调用获得免费资源；执行前拒绝不收费。每次恢复沿用累计状态，不重置预算、时间或决策上限。方案保存为本地持久化，不包含发布操作。
